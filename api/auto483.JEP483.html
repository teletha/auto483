auto483

JEP483

Provides support for Ahead-of-Time (AOT) class loading and linking, introduced by JEP 483 in Java 24 and streamlined by JEP 514 in Java 25.

This utility class helps in managing the creation and usage of AOT cache files. It aims to simplify the process of leveraging AOT compilation to potentially improve application startup performance.

The #enable() methods check for the existence of an AOT cache file. If the file doesn't exist, this class orchestrates the necessary steps to generate it. This involves restarting the application in a training run and creating the cache from the recorded configuration. The workflow is selected automatically from the running JDK version: a single step on JDK 25 or later, and a two-step record/create sequence on JDK 24.

JEP483()

enable()void

Enables Ahead-of-Time (AOT) loading and linking using the default cache file name .aot.

This is a convenience method that calls #enable(String) with ".aot" as the cache file name.

enable(StringcacheFileName)void

StringcacheFileName

The name (or path) of the AOT cache file to use or create. On JDK 24 this name is also used for the temporary AOT configuration file (-XX:AOTConfiguration, with "conf" appended); on JDK 25 or later the JVM manages that temporary file automatically.

Enables Ahead-of-Time (AOT) loading and linking using the specified cache file name.

This method checks if the specified AOT cache file exists. If it does not exist, it manages the process of generating the cache based on the current JVM execution mode:

  • Normal Mode (Attempting to use cache): If the JVM was started with -XX:AOTCache=<cacheFileName> but the file is missing, this method will restart the current application in a training run and wait until it terminates. On JDK 25 or later it uses the single-step workflow introduced by JEP 514 (-XX:AOTCacheOutput); on JDK 24 it uses the two-step workflow of JEP 483 (-XX:AOTMode=record followed by -XX:AOTMode=create). The current process is then terminated with the exit code of the process which ran the application.
  • Record Mode: If the JVM was started with -XX:AOTMode=record, this method does nothing. The process which started this one is responsible for creating the cache after this process has terminated.

If the cache file already exists, this method does nothing, allowing the JVM to load the AOT cache as configured.

Note: The cache generation process involves starting new JVM processes. Ensure that the necessary permissions and environment setup are in place for this to succeed. The classpath used for the cache generation process is derived from the current application's classpath.
